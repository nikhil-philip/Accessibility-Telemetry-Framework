The Project, One Sentence

"I apply Statistical Process Control to accessibility defect scores across CI builds, so a quality gate can tell ordinary noise apart from a real regression, instead of using a fixed violation-count threshold."

SPC Meaning, One Line Each

  • Common cause — normal noise, leave it alone.
  • Special cause — a real signal, investigate it.
  • UCL/LCL — the lines a point almost never crosses by chance alone.
  • WECO/Nelson Rule 1 — one point beyond 3σ.
  • Trend — several builds moving the same direction.
  • Regression spike — one big same-build jump for the worse.
  • CUSUM/drift — a small, persistent lean building up quietly.
  • Cpu/Cpk — is the process's typical level comfortably inside spec, not just its worst moment.

Telemetry, Gate, Dashboard — One Line Each

  • Telemetry — one immutable JSON record per build; never rewritten, only added to.
  • PASS — zero gate reasons triggered.
  • WARN — at least one soft signal, zero hard ones; doesn't block CI.
  • FAIL — at least one hard signal (critical defect, ≥50 score, 3σ breach, regression spike, or Cpu<1.0); blocks CI.
  • Dashboard — reads and displays only; computes nothing itself, enforced by verify-dashboard.ts.
  • CI — read-only against the repo; telemetry from CI leaves only as a 30-day artifact, never a commit.

Why Cpk Is Separate — One Line

Experiment A is deliberately five different regimes, so a capability number computed on it would be statistically meaningless; Experiment B is deliberately one stable regime, built specifically so Cpk's stability assumption actually holds.

Main Limitations — Say These Plainly

  • Only 4 real production builds — nowhere near enough for the SPC methodology to be proven on real data yet.
  • The 10/5/2/1 severity weights and the USL=40 example are policy choices, not empirically derived from this project's own data.
  • CUSUM's k/h constants are textbook defaults, not tuned against this project's telemetry.
  • No long-term production history exists yet to validate against.
  • ARCHITECTURE.md (the planning document) has drifted from the implementation in several small, named ways — see Architecture → Discrepancies.
