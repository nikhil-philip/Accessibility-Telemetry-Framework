Commands

Every command below is copied verbatim from package.json's "scripts" block — nothing here is invented. Run them from inside accessibility-telemetry-framework/.

Read-only vs. file-generating

READ-ONLY commands never write to telemetry/ or dashboard/ — safe to run any time. GENERATES FILES commands write or regenerate data on disk — the generate:* and verify:experiment/verify:stable-cohort commands regenerate the seeded experiment cohorts (deterministically, from a fixed seed, so re-running produces byte-identical output), and test:a11y appends a brand-new record to telemetry/history/.

Command Table

CommandTypeWhat it doesWhy it mattersExpected resultWhen to run it
npm run verify generates files Runs all six regression-guard scripts in sequence: verify:spc, verify:gates, verify:experiment, verify:stable-cohort, verify:dashboard, verify:ci. The single command that proves every layer still behaves exactly as previously validated, all at once. Every sub-script prints its own "=== Results: N passed, 0 failed ===" line; the combined command exits 0 only if all six do. Before a demo, and any time you want a single "is everything still OK" answer.
npm run verify:spc read-only Verifies the SPC engine (src/spc/) in isolation, including the real telemetry/history/ data. Confirms the control chart math and every rule/detector still fire correctly on known synthetic and real inputs. 30 check() assertions in the source; a clean run ends with "=== Results: 30 passed, 0 failed ===." After touching anything under src/spc/.
npm run verify:gates read-only Verifies the Quality Gate engine (src/gates/) against hand-built and end-to-end fixtures. Confirms every threshold in gatePolicies.ts produces the correct PASS/WARN/FAIL. 56 check() assertions in the source; a clean run ends with "=== Results: 56 passed, 0 failed ===." After touching anything under src/gates/.
npm run verify:experiment generates files Regenerates and verifies Experiment A's 30-build cohort — reproducibility, schema, phase boundaries, engine/gate compatibility, and that Cpk is correctly excluded. Confirms the baseline-methodology dataset used throughout the Experiments page is exactly reproducible. 52 check() assertions; a clean run ends with "=== Results: 52 passed, 0 failed ===." After touching src/telemetry/experimentGenerator.ts or src/spc/experimentAnalysis.ts.
npm run verify:stable-cohort generates files Regenerates and verifies Experiment B's 30-build stable cohort, including a hand-computed cross-check of the Cpu formula. Confirms the capability-analysis dataset is exactly reproducible and its stability assumption actually holds. 30 check() assertions; a clean run ends with "=== Results: 30 passed, 0 failed ===." After touching src/telemetry/stableProcessGenerator.ts or src/spc/capabilityAnalysis.ts.
npm run verify:dashboard read-only (inspects dashboard/ only if it already exists) Confirms buildDashboardData() never mutates source telemetry, that every number matches calling L4/L5/L6 directly, and that the known validated results (Experiment A pass/warn/fail counts, Cpu≈2.9811) still hold. This is the check that proves L7 is presentation-only, not just documented as such. 32 check() assertions; a clean run ends with "=== Results: 32 passed, 0 failed ===." After touching anything under src/dashboard/.
npm run verify:ci read-only Verifies ciAdapter.ts's exit-code mapping with fixed fixtures, and statically validates accessibility-ci.yml — every npm run it invokes exists, every script file it resolves to exists, and no failure-hiding pattern (|| true, continue-on-error: true) is present. Catches a broken or drifted CI workflow before it ever runs on GitHub. 28 check() assertions; a clean run ends with "=== Results: 28 passed, 0 failed ===." After touching src/gates/ciAdapter.ts or the workflow YAML.
npm run generate:experiment generates files Wipes and regenerates telemetry/experiments/spc-validation-cohort/ (30 files), and prints a build-by-build comparison table of both analysis methods. Produces the raw data Experiment A is built from. Console table plus 30 new/overwritten JSON files. Only if you deliberately want to regenerate Experiment A's data (it's already committed and reproducible from the fixed seed).
npm run generate:stable-cohort generates files Wipes and regenerates telemetry/experiments/stable-capability-cohort/ (30 files) and prints the Cpu/capability result. Produces the raw data Experiment B is built from. Console output plus 30 new/overwritten JSON files. Only if you deliberately want to regenerate Experiment B's data.
npm run generate:dashboard generates files Builds dashboard/ from scratch: index.html, assets/, and data.json, from the current telemetry + experiment data. This is what actually produces the dashboard you can open in a browser. A new dashboard/ folder on disk. Any time you want to look at the current dashboard, or before npm run test:dashboard.
npm run serve:dashboard generates files Runs generate:dashboard, then starts a plain static file server on port 4310 (override with DASHBOARD_PORT). The easiest way to actually view the dashboard in a real browser. Console log "serving on http://localhost:4310"; leave it running and open that URL. Whenever you want to show the dashboard live, e.g. in a reviewer demo.
npm run gate:ci generates files Evaluates the quality gate against whatever is currently in telemetry/history/, writes telemetry/aggregated/gate-verdict.json, and exits 0 (PASS/WARN) or 1 (FAIL). This is the literal command CI runs to decide merge/no-merge. Console output showing status, reasons, and "Quality Gate: <STATUS> — CI continues." or "… — blocking the build." Any time you want to know, right now, what verdict the current telemetry history would produce.
npm run test:a11y generates files Runs Playwright against tests/accessibility/*.spec.ts — scans all 8 ShopSmart routes with axe-core and writes a new telemetry record. The actual accessibility scan; this is what feeds everything downstream. Playwright's own test report (8+ tests passing/failing per the axe assertions), plus one new file in telemetry/history/. To generate fresh, real telemetry, or before npm run gate:ci if you want a brand-new build to gate on.
npm run test:functional read-only Runs the one functional (non-accessibility) test, tests/functional/checkout-flow.spec.ts. Shows the framework isn't accessibility-only — it's a general Playwright QA base. Playwright report, one test passing. To demonstrate the checkout flow works end-to-end.
npm run test:dashboard read-only (requires dashboard/ to already exist) Runs the browser smoke test against a live-served dashboard. Proves the dashboard actually renders and is keyboard-navigable in a real browser, not just that the generator didn't crash. 1 test passing, checking headings, badges, the rendered SVG chart, and keyboard reachability. After generate:dashboard, to confirm the generated site actually works.
npm run test:dashboard:a11y read-only (requires dashboard/ to already exist) Runs axe-core against the dashboard itself, in both light and dark mode. Proves the dashboard doesn't violate the same accessibility rules it's built to monitor. 2 tests passing (light + dark), each asserting zero axe violations. After generate:dashboard.
npm run report read-only Opens Playwright's HTML report from reports/html in a browser. The easiest way to inspect individual test failures/screenshots after a run. A local browser tab with the interactive Playwright report. Right after any test* command, to inspect results in detail.
Note on expected outputs above

The "expected result" column for the verify:* scripts (e.g. "30 passed, 0 failed") is derived by counting the exact number of check() calls present in each script's source, and quoting each script's own final-line format (console.log(\`\n=== Results: ${passCount} passed, ${failCount} failed ===\`)). This documentation session did not execute the scripts, in keeping with a documentation-only, implementation-frozen scope — the counts are read directly from the code, not from a captured console log.
