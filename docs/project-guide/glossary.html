Glossary

Every term explained in plain, beginner-friendly language. Alphabetical.

AccessibilityMaking a website usable by people with disabilities — for example, someone using a screen reader, or someone who can't use a mouse and navigates entirely by keyboard.
ArtifactA file (or folder of files) a CI run produces and uploads for download, without committing it to the repository. This project uploads the dashboard, telemetry, and gate verdict as an artifact, retained 30 days.
axe-coreThe open-source accessibility rule engine (by Deque) that actually inspects a web page's HTML and reports WCAG violations. This project uses it via @axe-core/playwright; it doesn't reimplement any of its rule logic.
BuildOne run of the test suite — one point in time where the accessibility tests executed and produced a result.
Common cause (variation)Ordinary, expected noise in a process. Nothing to investigate — the process is "in control."
Control chartA chart plotting a measurement over time, with a center line (the average) and two control limits (UCL/LCL) marking where a point becomes statistically surprising.
Cpu / CpkA process capability index — a single number describing whether a process's typical behavior comfortably clears a quality specification, not just whether it's stable. This project computes the one-sided version, Cpu, against an upper specification limit.
CI/CDContinuous Integration / Continuous Delivery — automatically running tests (and other checks) every time code changes, instead of a human remembering to run them manually.
CUSUM"Cumulative sum" — a statistical technique that adds up small deviations from the average over time, designed to catch a slow, persistent shift that no single point would trigger on its own.
DefectOne accessibility problem axe-core found — for example, an image missing alt text.
Defect scoreThe single number this whole project is built around: 10×critical + 5×serious + 2×moderate + 1×minor, summed across every defect found in one build.
DriftA slow, sustained shift in one direction, detected here by CUSUM — the software equivalent of a machine slowly going out of calibration.
Expanding historyAn analysis method that always looks at every build so far, from build 1 up to the current one — the window only ever grows.
LCL (Lower Control Limit)The line below which a measurement is statistically surprising on the low side. Clamped at 0 here, since a defect score can't be negative.
MeanThe plain average of a set of numbers.
Nelson (rules)Eight pattern-detection rules (Lloyd S. Nelson, 1984) that flag a control chart as "out of control" based on the shape of recent points, not just a single point crossing a limit.
PlaywrightA browser automation tool (by Microsoft) used here to launch a real Chromium browser, navigate ShopSmart's pages, and host the axe-core scan.
Quality gateThe component that looks at a build's numbers and statistical signals and decides PASS, WARN, or FAIL.
PASSNo gate reason triggered at all. Exit code 0; doesn't block CI.
WARNAt least one soft signal triggered (e.g. a worsening trend), but nothing severe enough to hard-fail. Exit code 0; doesn't block CI, but is visible everywhere.
FAILAt least one hard signal triggered (e.g. a critical defect, a 3-sigma breach, a regression spike). Exit code 1; blocks CI if branch protection requires the check.
Regression spikeA same-build shock: this build's score jumped by an unusually large amount, in the bad direction, compared to the previous build.
SPC (Statistical Process Control)A discipline, originally from manufacturing, for monitoring a repeated measurement over time and distinguishing ordinary variation from a genuine problem.
Special cause (variation)A signal that something structurally changed — a real regression or a real improvement. Worth investigating.
Sigma (σ)Standard deviation — a single number describing how far measurements typically spread out from the average. This project estimates it from the average moving range: σ̂ = MR̄ / 1.128.
TelemetryMeasurements collected automatically over time. Here: one small JSON record written per build, kept forever.
Trailing windowAn analysis method that only looks at the most recent N builds (15, in this project's experiment tooling) — older builds age out and are no longer part of the current calculation.
UCL (Upper Control Limit)The line above which a measurement is statistically surprising on the high side — roughly 3 standard deviations above the average.
USL (Upper Specification Limit)An agreed-upon "worst acceptable" value for the process — a policy number, not something SPC derives on its own. This project uses USL=40 as an illustrative example in Experiment B.
Walk-forward (analysis)Evaluating a build using only the data available up to and including that build — never peeking at future builds. Both experiment analysis methods work this way.
WCAGWeb Content Accessibility Guidelines — the W3C standard this project tests against, at level AA.
WECO (Western Electric rules)Four classic pattern-detection rules (from the 1956 Western Electric Statistical Quality Control Handbook) — the historical predecessor to Nelson's later, larger rule set.
Every definition above matches how the term is actually used in this project's code and documentation, not just a textbook definition.
